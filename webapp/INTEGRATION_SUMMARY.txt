3. WHAT'S SUPPORTED
   Feature                  | Support | Notes
   ======================== | ======= | ========================================
   Multi-round context      | YES     | via session_id + resume parameter
   Streaming responses      | YES     | AssistantMessage token-by-token
   Tool whitelisting        | YES     | allowed_tools + Hook validation
   Bash command whitelist   | YES     | PreToolUse hook + regex matching
   Multi-session isolation  | YES     | One process, memory-isolated sessions
   File I/O interception    | YES     | PostToolUse hook for audit logging
   Tool execution control   | YES     | HookMatcher + custom async functions
   Failure recovery         | MANUAL  | Catch ProcessError, rebuild session

4. WHAT'S NOT SUPPORTED
   ✗ Sandbox isolation (all sessions share cwd)
   ✗ Fine-grained Read file path restrictions (use hooks)
   ✗ Subprocess management (SDK internal, not exposed)
   ✗ Session persistence to disk (in-memory only, lost on restart)

5. ARCHITECTURE
   Frontend (React/Vue) <--WebSocket--> FastAPI Backend <--async--> Claude Agent SDK
                                                             |
                                            ┌────────────────┴──── Claude Code CLI
                                            |
                                      In-process query loop
                                      (async generators)

   Per-client flow:
   1. User connects → backend creates ChatAgent(client_id)
   2. ChatAgent.init_session() → captures session_id from SDK
   3. User sends prompt → ChatAgent.send_message(prompt)
   4. SDK streams AssistantMessage/ResultMessage back
   5. Backend re-streams to WebSocket client (JSON)
   6. On disconnect or crash → cleanup, session deleted
